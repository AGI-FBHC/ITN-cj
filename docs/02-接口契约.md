# 仓颉内核接口契约

## 对话知识网络（2026-10-16）

- `/api/knowledge/graph {}`返回主节点与用户手动连线；默认无边、无子节点。`/api/knowledge/node {id}`返回概念、别名、来源问答记录、工作区快照和关联笔记。
- `/api/knowledge/save {id?,title,definition,aliases?}`为用户手工新增/编辑；模型通过`record_knowledge_point {title,definition,quote,note,aliases?}`记录实质知识讨论，quote须来自本轮用户原话，闲聊与一次性制文件指令不记录。概念按标准化标题/明确别名合并，记录按节点+会话+轮次幂等，模型不能覆盖用户编辑的定义。
- `/api/knowledge/note {id,text}`新增关联笔记，复用notes与全文索引；`/api/knowledge/link {from,to,label?,remove?}`仅显式手工连接，拒绝自连或不存在节点；`/api/knowledge/delete {id}`删除节点/来源记录/连线，保留本人笔记。
- 节点、定义、记录与关联笔记进入全局内容索引。针对节点提问必须新建会话，按所选来源记录的projectId回到原工作区；项目已删除时必须由用户选择新的去向，不静默换目录。

## 个性资源与内容索引（2026-10-16）

- `POST /api/personal/list {}`：扫描已确认目录，返回`{directory,resources:[{id,title,path,kind,version,createdAt,learningId,sessionId,turnId}]}`。默认`<dataDir>/artifacts`，未来生成候选一律先放`drafts`；目录内已有文件保留并登记。
- `POST /api/personal/settings {directory?}`：读取/设置个性资源目录，只创建目录，不移动或删除已有资源。
- `POST /api/personal/save {path,title?,text?,learningId?,sessionId?,turnId?,confirmed:true}`：用户确认后创建独立副本，保留先前确认版本；相同来源且字节相同不重复保存。同步持久内容索引，复制PPT设计/预览伴随文件。
- `POST /api/personal/search {query,limit?}`：检索个性资源、笔记和错题的持久正文索引，返回`{hits:[{type,id,title,snippet,path?,learningId?}]}`；参数化字面匹配，不执行用户查询。笔记/作答保存后同步索引，删除笔记移除索引。
- Agent提供`search_personal_resources`、`read_personal_resource`、`save_personal_resource`；保存工具仅在本轮用户明确要求存入/保存到个性资源时可执行，不能用“做完了”替代确认。未确认草稿不加入跨会话个性检索。
- Agent的`search_personal_resources`带`query`时行为不变（全文匹配）；`query`为空时返回总览`{counts:{knowledge,resource,note,wrong},hits:[按更新时间倒序的最近条目]}`，`type=knowledge|resource|note|wrong`可只看某一类。回答“我的知识网络/笔记/错题里有什么”必须用空query总览或`type`列举，空命中不能解读为“没有内容”（2026-10-17修复：此前空query直接返回空数组，模型据此回答“0条”）。
- Agent的`get_learning_context`新增`knowledge:{total,recent:[{id,title,color,recordCount,updatedAt}]}`（知识网络概况，最多8个最近节点）；询问知识网络前先读它，节点详情用`read_knowledge_point`。

## Agent制作PPTX（2026-10-16）

- `create_presentation`领域工具接收`{title,audience,purpose,style,slides:[{title,layout,bullets?,columns?,metrics?,notes?}]}`。先确认受众/目的/页数/风格；用户明确免确认或已确认细节才执行。生成真实可编辑PPTX，不把现有Markdown直接转换冒充Agent重新设计。
- 内核创建`desktop_jobs`，桌面主进程领取并用随包PptxGenJS构建到`<数据目录>/drafts`，同时保存设计JSON和HTML预览；完成发`artifact/created`，仍为候选产物，不自动存入个性资源。
- `POST /api/desktop/jobs/list {}`返回待处理任务；`/claim {id}`原子领取；`/finish {id,ok,result?,error?}`写入结果。工具等待有超时和停止检查，桌面退出/取消不能报成功。

## 长工具参数与等待状态（2026-10-16）

- 模型请求沿用8192默认输出额度；纯思考或工具参数输出被`finish_reason=length`截断且没有正文时，允许一次以32768额度重新请求，记录`model/retry`；MiMo恢复轮用官方`thinking.type=disabled`确保开始输出，正常轮保留原思考行为。MiMo纯思考阶段超过24000字节且尚无正文/工具时，提前进入同一有限恢复流程，防止把全部输出额度耗在思考；这是客户端字节预算，不宣称token数。不会执行被截断/非对象/非法JSON参数，也不将其修补为`{}`；再次截断明确报错，保留已展示过程。MiMo工具历史完整回传`reasoning_content`。
- `assistant/activity`增加`phase=tool_input`、`tool`、`receivedBytes`，表示正在接收工具参数，尚未执行工具；进度事件限频，不保存参数正文。模型审计记录`maxOutputTokens`、截断原因和重试额度。
- 界面等待计时按本地时钟更新，不依赖新事件；计时仅更新文字，避免每秒重建整轮Markdown。

## 学讲义与节进度（2026-10-16）

- `POST /api/study/course {kbId}` → `{chapters:[{name,title?,sourceChapter,resourceId,version,citations,sections:[{id,title,markdown,done}],doneCount,sectionCount}],sectionCount,doneCount,next:{chapter,sectionId,title}?}`。目录使用讲义自身的章与节结构；sourceChapter记录资料来源章节。每章优先最新已明确绑定该章或topic/title精确匹配的讲义，正文直接来自结构化讲义；缺少讲义时仅用原文标题组成目录，正文留空。
- `POST /api/study/lecture {kbId,chapter,sessionId}`：就地调用现有`generate_learning_resource`领域工具，强制保存`studyChapter`；会话事件持续返回`resource/progress`和`resource/saved`，响应为资源id等工具结果；不跳对话页。按知识库/章节防重复生成。
- `POST /api/study/section/complete {kbId,chapter,sectionId}`：校验当前课程的节，幂等写入现有`progress`表的`kind=section`。旧原文阅读记录保留，不能用已读片段推断学完一节。`/api/study/report`另回`completedSections`供成长页展示。
- `/api/study/quiz/generate`可带`sectionId`：使用已生成的该节讲义为材料、固定3题；`/api/study/quiz/submit`可带`sectionId`，题目元数据记录节归属，继续复用原作答与错题记录。

## 会话全文检索与定位（2026-10-16）

- `POST /api/sessions/search {query, limit?}`：搜索标题及用户/助手正文（包含非当前分支，流式正文按轮合并），返回 `{hits:[{sessionId,title,turnId,snippet,role,at}]}`；空查询不搜，最多返回50项，纯文本匹配，不把输入作为SQL通配符。
- `POST /api/sessions/reveal {sessionId,turnId}`：命中已在当前分支时保持末端不变；否则切到包含该轮的最新后代末端，保留后续消息；返回 `{ok,leaf}`。任务运行/停止中拒绝切换；不存在返回错误，不删除事件。

## 资料收集与确认并入（2026-10-15，R29）

以下接口均为 POST，沿用 `{code,data,message}` 包装。

| 路径 | 请求 | 结果 |
| --- | --- | --- |
| `/api/kb/stage` | `{kind:"url"或"repo",url,ref?}` | 暂存来源：id/kind/url/ref/完整commit/fetchedAt/files[{path,bytes}]/skipped/status |
| `/api/kb/sources` | `{}` | `{sources:[...]}`，包含 staged / ingested / discarded 状态 |
| `/api/kb/source/preview` | `{id,path}` | `{text}`，最多20KB，用于用户检查实际内容 |
| `/api/kb/source/refetch` | `{id}` | 新的暂存快照，原记录与已并入文件保持原样 |
| `/api/kb/source/discard` | `{id}` | 只将待并入来源标为 discarded，保留审计文件 |
| `/api/kb/ingest` | `{id,kbId,confirmed:true}` | 用户确认后复制到库目录 sources/id，随后界面调用既有 `/api/kb/build`；重建失败保留来源和明确重试入口 |

暂存不进索引，来源清单以数据目录 staging/id/.source.json 为权威，随库副本保留同一清单。
不新增与清单重复的 knowledge_bases 字段：一个库可以有多个独立来源。
GitHub只使用 api.github.com，先解析完整commit再固定读取对应blob；拒绝截断文件树，
上限300个文本文件、单文件4MB、总量32MB，跳过点目录/node_modules/dist/target。
`kb_stage` 是 lumin 联网工具；`kb_ingest` 只返回 requiresConfirmation 与界面指引，
模型没有可用的确认参数。实际并入只能由界面显式确认触发。

### lumin 宿主技能边界

`/api/agent/ask-pi` 的 `skill` 指定本轮技能。禁用/不存在的技能返回 `ok:false`，
记录 `skill/unavailable`，不调用模型。未指定时只把可用技能元信息放进提示词，
模型按需调用 `skill_read`。显式绑定或读取成功后，宿主在 `beforeToolCall`
强制检查技能的 tools 清单；越权调用返回错误并记录 `tool/denied`，不执行工具。
这项检查与原有权限审批组合，二者均通过才执行。

模型接口连续90秒未返回增量时，以失败终态结束，不自动重试同一个沉默请求；
返回空的完成消息同样视为失败。取消会主动关闭本轮HTTP客户端，即便尚无任何SSE增量也可中断。
已经收到的正文与工具事件保留用于回看，停止后不会开启下一轮模型请求。

### 取消与实时状态补充（2026-10-15）

`/api/agent/cancel` 对正在执行的联网搜索、网页读取与审批等待也生效。
界面确认取消请求后显示“正在停止”，收到本轮 turn/end 后才显示已取消。
轮询收到终态即收起忙碌状态，不依赖原生成HTTP响应先返回；停止始终针对实际在运行的会话。
`assistant/activity` 只记"模型在思考"这件事（每秒最多一条，供运行态提示）；
`assistant/thinking` 记思考正文的一段（按"开始出正文 / 开始动工具 / 这一轮结束"切段，
payload `{text, ms}`，正文截断到 6000 字节），界面渲染成 Codex 那种「已思考 N 秒」折叠行。
工具事件保留真实 toolCallId，用于同时调用同名工具时匹配结果。

外壳与内核之间的唯一通道。内核只监听 `127.0.0.1`，端口由系统分配，并把实际端口写入启动参数 `--port-file` 指定的文件。

## 启动参数

| 参数 | 说明 |
| --- | --- |
| `--data-dir <路径>` | 本地数据目录，默认 `%LOCALAPPDATA%\ITN-Desktop` |
| `--port-file <路径>` | 内核写入实际监听端口；外壳读取此文件完成握手 |

两种写法都支持：`--flag value` 与 `--flag=value`。

## 响应约定

成功：`{"code":0,"data":<内容>}`；失败：`{"code":1,"message":"<原因>"}`，并带对应 HTTP 状态码（400 参数问题、404 找不到、500 内部错误）。

## 安全与行为约定

- `apiKey` 永不回传，只回传 `hasApiKey` 布尔值。
- `save` 时若请求未带 `apiKey`（空字符串），保留原有密钥，避免外壳只改模型名时把密钥清空。
- `delete` 会同时清空引用该模型的三个用途绑定。
- 所有接口统一走 OpenAI 兼容格式：`POST {baseUrl}/chat/completions` 与 `POST {baseUrl}/embeddings`。

## 知识库的处理约定

- 可读格式：`.md` / `.markdown` / `.txt` / `.text` / `.csv` / `.tsv` / `.log` / `.json` / `.html` / `.htm`，递归扫描子目录。
  HTML 会先转成文本（去掉 `script`/`style`，`h1`~`h6` 变成 Markdown 标题，因此照样按标题分章）。
- 读不了的文件**不静默跳过**：`/api/kb/build` 的返回里带 `skipped`（`[{ext, count}]`）、`skippedSummary`（形如 `pdf ×3、docx ×1`）、
  `skippedTotal`；同一份摘要也会写进 `meta`（键 `kb-skipped:<kbId>`），由 `/api/kb/stats` 回传，界面可随时回看。
  图片（png/jpg/…）与系统文件（exe/dll/db/…）不计入"未纳入"，前者本来就是被文档引用的附件。
- 单文件超过 4 MB 会被跳过并计入 `skippedSummary` 的「超过体积上限 ×N」。
- 隐藏目录与 `node_modules`/`target`/`dist` 不扫描；**点开头的文件**（`.nojekyll`、`.DS_Store` 等）不算"读不了的资料"，不进 `skippedSummary`。
- **导入**（`/api/kb/import`）两种形态共用一条入口：`kind` 为 `dir` 时**原地登记**（不复制），为 `file` 时把这份文件复制进
  `<dataDir>/kb/<id>/source/`（**连同它引用的相对路径图片**一起复制，原文件挪走/改名也不影响知识库）；`kind` 省略或为其他值按"自动判断"处理。
  `id` 省略时按「去掉扩展名的文件名 → 显示名 → `kb`」挤英文短名并自动去重；返回的 `imported` 里有 `{ok, kind, rootDir, source, copied, docs, note, id}`。
  登记里存 `sourcePath`（导入的原始路径）：**同一处资料再导入一次会复用原来的知识库**（不会又建一个），原文件更新后重新导入即可刷新。
- **分章自适应**：材料有 Markdown 标题就按标题；没有就认材料自己的编号——`第X章/篇/部/单(元)` 与 `一、` 是一级，
  `第X节/讲/课/目` 与 `1.` 是二级，`1.1.1` 是三级（要求该行短、不以句读结尾、后面确实跟着一段正文）；
  两者都没有且篇幅超过 3×`maxChars` 时，按长度切块并用每块头一行当节名。识别不出来就退回"一片一篇档"的原行为。
- 按 Markdown 标题层级切块；代码围栏内的内容不参与标题判定，也不会被切开。
- `maxChars` 默认 1200，超过即切块，避免单块过大。
- 图片引用（`![](相对路径)`）随所属切片一起记录；建索引时为含图片的切片调用多模态模型生成描述，写入 `caption`。
- 参与向量化的文本是「正文 + [图片描述]」，因此图片内容可被检索命中。
- 图片相对路径会拒绝绝对路径与 `..` 跳转，避免越出知识库目录。

## 会话事件

会话日志是只追加的 JSONL，每个会话一个文件，放在 `<dataDir>/sessions/<sessionId>.jsonl`。事件类型与触发时机：

| 事件 | 含义 |
| --- | --- |
| `turn/start` | 一轮开始，payload 带 `kind`（ask / lecture / quiz）与 `kbId`（这一轮用的知识库） |
| `assistant/delta` | **流式增量**：模型每吐一段正文就写一条，payload 带 `text`。界面轮询它做"打字机"效果；最终答案以 `assistant/message` 为准，delta 是**暂定的**（那一轮如果其实是工具调用，delta 里会是工具 JSON，界面收到 `tool/call` 后应丢弃这一段） |
| `assistant/thinking` | 一段思考的正文与耗时：`{text, ms}`。按"下一件事"切段（开始出正文 / 开始动工具 / 一轮结束），界面渲染成「已思考 N 秒」的折叠行；模型没用思考增量时不会有这条 |
| `user/message` | 用户输入 |
| `step/start` / `step/end` | 一步开始与结束，payload 带 `index` 与 `name` |
| `tool/call` / `tool/result` | 工具调用与结果摘要；`tool/call` 的 payload 带 `tool` 与 `args`（参数对象），`tool/result` 带 `tool`/`ok`/`summary` |
| `web/policy` | 这一轮的联网决策：`{mode, insufficient, webSearch, webFetch}` |
| `skill/read` | 这一轮用了哪个技能：`{skill, title, tools}`（用户点名用的，或模型自己 `skill_read` 读的） |
| `skill/unavailable` | 想用但用不了的技能及原因：`{skill, reason}`（没声明 tools、或要联网而档位是"不联网"） |
| `tool/denied` | 技能没声明的工具被调用（已拒绝）：`{tool, skill}` |
| `assistant/message` | 模型回复 |
| `validation` | 引用自检结果，payload 带 `report` |
| `turn/end` | 一轮结束，payload 带 `ok` 与可选的 `message` |

一次典型问答产生 14 条事件。日志是"答案可溯源、产物可复现"的落地方式：产物里的每个引用编号都能对回当时的检索结果。

## 引用自检

生成类接口（讲义、练习）与问答都会跑一次引用自检，返回 `citationReport`：

```json
{ "paragraphs": 6, "citedParagraphs": 5, "outOfRange": 0 }
```

`paragraphs` 是正文段落数（跳过标题行），`citedParagraphs` 是至少带一个 `[n]` 标记的段落数，`outOfRange` 是引用了不存在编号的次数。讲义与练习的产物末尾会附「资料来源」章节，列出每个编号对应的文档与标题路径。

## 产物

生成结果写入 `<dataDir>/artifacts/`，文件名形如 `讲义-<主题>.md`、`练习-<主题>.md`。文件名中的路径分隔符与通配符会被替换，避免越出目录。

## 实现注意

- **新增接口必须同时登记路由白名单**：内核用的是精确路径匹配的分发器（`buildServer` 里的 `routes` 数组），
  只加 handler 不登记白名单，请求会直接 404，而且不会打印任何日志（踩过一次：`/api/websearch/*` 全部 404）。
- 界面静态文件只允许 `index.html` / `app.js` / `style.css` 三个（`statics` 白名单）；要加图片等资源必须同时改白名单。

默认的请求分发器按**精确路径**匹配，且不支持路径参数。因此所有路由都必须在 `core/src/api/api.cj` 的 `buildServer` 里显式注册；参数一律放在 JSON 请求体里，不用路径段和查询串。新增接口时记得同步那份路由列表。

## 错题的间隔复习

复习状态存在 `meta` 键值表里（不动表结构，老数据目录直接可用）：

| 键 | 值 |
| --- | --- |
| `quiz-review:<记录id>` | `重做答对次数\|上次复习毫秒\|是否已掌握(0/1)` |
| `quiz-q:<记录id>` | 原题 JSON：`{options, answerIndex, explain, source}`（只有新记录有） |

间隔节奏（`reviewIntervalMs`，写在 `api.cj` 一处）：答对 1 次后 1 天，2 次后 3 天，3 次后 7 天，4 次后 16 天，5 次及以上 35 天；
**没答对过的题（`reviews == 0`）当天就要复习**；标记「已掌握」后不再进入待复习，直到手动取消。

## Agent 工具与流式输出（2026-10-14 新增）

### `/api/agent/ask` 的新行为

| 项 | 说明 |
| --- | --- |
| 多轮上下文 | 传同一个 `sessionId` 即构成多轮对话。内核从会话事件里取最近 6 轮（12 条消息，单条截断到 800 字节且不切断多字节字符）拼进 messages |
| 工具调用 | 模型可以在作答前调用本地工具，最多 4 轮（`guard < 5`）。工具结果回填后模型再作答 |
| 返回新增字段 | `toolCalls`（本轮调用次数）、`toolsUsed`（工具名数组） |
| 技能 | 请求可带 `skill: "<id>"`：**显式指定**就把它正文直接装进提示词，并只允许它 `tools:` 里声明的工具（其他调用被拒并记 `tool/denied`）；不指定就把技能清单放进提示词，由模型自己 `skill_read` |
| 联网决策 | 请求可带 `web: "auto"/"always"/"off"`（会话级，优先于全局设置）。每轮开始会写一条 `web/policy` 事件：`{mode, insufficient, webSearch, webFetch}`——**是否联网由 agent 自己判断**，这一条就是它判断的结果，留在会话里可回看 |
| 引用分级 | 本机资料用 `[n]`、抓回来的网页用 `[Wn]`。返回的 `citations` 里网络来源带 `kind:"web"`、`label:"W1"`、`fetchedAt` 与原始链接；`citationReport` 额外给 `webCited` / `outOfRangeWeb` |
| 流式 | 每段正文写一条 `assistant/delta` 事件。内核 HTTP 服务是多线程的，长生成不会挡住 `sessions/events` 等请求，所以界面用轮询即可，不需要 SSE |
| 失败 | 仍然返回 `{ok:false, message}`，并把原因写进 `turn/end` |

### 工具协议（不依赖供应商的 function calling）

系统提示词里会列出工具清单，并要求模型需要工具时**只输出一行 JSON**：

```json
{"tool":"calc","args":{"expr":"(12+8)*3/4"}}
```

内核从回复里提取第一个合法的 `{"tool":...}` 对象（按花括号配对扫描，跳过字符串与转义），执行后把结果拼成文本追加进 messages 再让模型继续。
这样任何只提供 `/chat/completions` 的 OpenAI 兼容服务都能跑工具，不需要供应商支持 `tools` 字段。

### 内置工具（`/api/tools/list`）

| 名字 | 用途 | 参数 |
| --- | --- | --- |
| `kb_search` | 检索当前知识库 | `{query, top_k?}` |
| `list_documents` | 列出知识库文档与切片数 | `{}` |
| `read_chunk` | 按切片 id 取原文 | `{chunk_id}` |
| `current_time` | 本机当前时间 | `{}` |
| `calc` | 四则运算（`+ - * / %` 与括号） | `{expr}` |
| `save_note` | 写一条学习笔记（落本机库） | `{title, text}` |
| `save_artifact` | 写一份 Markdown 产物到 artifacts | `{name, content}` |

工具结果文本里，检索类结果统一用 `[T1]` 前缀编号，与正文引用 `[n]` 区分，避免模型拿工具序号去引用、与界面出处列表对不上。

## 课件播放进度

「按页播放」的进度存在 SQLite 的 `meta` 键值表里，键为 `artprog:<产物名>`，值为 `页码|总页数|更新时间`。
键名用的是传给接口的 `name`，因此界面上「整章按节播放」也会用自己的键（`chapter:<知识库id>:<章节名>`）记录进度，
与产物互不干扰。这套进度只是"上次看到第几页"，丢了不影响任何内容。

- `POST /api/sessions/state {sessionId}` 返回 `{sessionId,turnId,status,canResume}`；状态 running/cancelling/completed/failed/cancelled/interrupted。进程重启后无运行实例的任务记 interrupted。
- 同会话仅允许运行一轮；不同会话互不覆盖。cancel 可带 turnId，过期 turnId 返回 409。运行时禁止删除会话。
- 新增资源工具 generate_learning_resource/read_learning_resource/revise_learning_resource；kind 为 lecture/practice/quiz/ppt。结构化资源落 SQLite，带稳定 id、版本、质量、来源与画像快照；在线演示不要求 pptx。
- 新增学习工具 get_learning_context/remember_learning_fact/forget_learning_fact。记忆须关联明确用户原话或用户手动编辑；测验依据服务端资源答案评价，阅读进度不当作掌握度。
- `/api/learning/resources`、`/api/learning/resource`、`/api/learning/answer`、`/api/learning/context`、`/api/learning/memories`、`/api/learning/memory/save`、`/api/learning/memory/forget` 均 POST；详见实现和方案文档。
- `/api/learning/resource` 返回指定版本 `answers`（按题目 id 的最近作答），重开资源可恢复反馈。`/api/learning/progress {id,version,done}` 保存本人完成标记。
- `/api/learning/memory/policy {autoRemember?:boolean}` 读取/设置自动积累开关。关闭后仍允许本人在管理页添加，或在对话中明确要求“记住”。
- 资源引用保留生成时的切片快照与编号；演示播放器按结构化 slides 精确分页，Markdown 是导出格式。版本差异通过读取两个不可变版本计算。
- 首次启动新增资源登记迁移：既有 artifacts/*.md 以 kind=legacy、版本1 保存原文与路径快照，不推测结构化题目、来源或生成画像，原文件保留；迁移标记落 meta。历史资料在资源库可读，若要转换为四类资源，revise_learning_resource 需明确 kind。


## 2026-10-16 非对话页面第一批：资料清单与预览
- `POST /api/kb/stats {id}` 的 docs 保留 path/title/chunks/images，新增 `sizeBytes`（当前源文件大小，-1 表示不可用）、`preparedAt`（整库最近准备时间）、`status`（ready 已准备 / pending 新文件待准备 / missing 原文件不在当前扫描范围 / unknown 源目录不可读）。扫描仅覆盖内核已支持的文本格式，未支持/过大文件仍由 skippedSummary 解释；不推测文件更新状态。

- 本批不增加单篇重建/移除或后台取消接口。重新准备仍调用既有 `/api/kb/build`，明确作用于整库、保留原文件。

## 2026-10-17 思维导图生成提速、进度与 token 统计（0.8.13）
- 逐批提炼改为并行：默认 3 个 worker（每批独立 provider，单批失败重试一次，worker 间进度用锁同步）；合并大纲按轮并行，最多 5 轮，仍未收敛明确报错请精简资料。批量 30,000 字节/批，单批摘要 ≤1200 字；树生成输出预算 16k tokens、节点上限 120（其余调用保持 8k）。
- 批次摘要缓存 `course_summary_cache(kb_id,batch_key,summary,at)`：batch_key 为批次文本指纹；每批完成立即落库，取消/失败后重试可续跑；知识库内容不变的二次生成只重算树（摘要全部命中）。
- `/api/course/job` 与 `state().job` 新增 `progress{percent,phase,done,total,etaSeconds}` 与 `tokens{in,out,total,calls}`：百分比单调（读库→逐批 5–65%→合并 65–75%→树 78–92%→保存 94%→完成 100%）；ETA 由已完成批次平均耗时估算。任务 20 分钟没有任何进展会被判定失败（旧导图保留）；新建任务会清理该知识库的历史失败/取消任务记录。
- 学·练界面：生成中显示阶段、百分比、进度条、预计剩余、累计 token（入/出）与取消按钮。

## 2026-10-17 思维导图学习与资源生命周期（实施契约）
- 一知识库只有一个当前导图；树根计第1级，最多4级，LLM全库分批归纳后校验节点与出处。首次生成自动发布；重建先生成候选，用户确认publish才切换，旧节点资源归档。取消/失败保留旧图。
- POST /api/course/state {kbId}：当前图、来源变化、四类当前资源、归档/回收站数量、生成任务；/generate {kbId,jobId?}：固定后台LLM流程，/job {id}：阶段/失败/候选；/cancel {id}；/publish {mapId,expectedMapId,confirmed:true}：并发检查与切换；/history {kbId}：历史树快照。
- POST /api/course/node {kbId,nodeId,title?,parentId?,remove?,subtree?,confirmed?}：节点读取/编辑/移动/删除，ID保持，拒绝循环/超过4级/删除根。删除默认子节点上移；subtree=true删除整支，资源归档。
- POST /api/course/start {kbId,nodeId,kind,projectId?,regenerate?}：创建或返回节点会话，服务器保存kb/map/node/kind与当前资源版本快照，不依赖前端提示词认归属。普通会话不把KB目录当写目录；已删除项目禁止静默改投。
- POST /api/course/target {sessionId}：节点目标及是否失效；/commit {sessionId,path,learningId?,learningVersion?,title?,expectedResourceId,confirmed:true,targetNodeId?}：候选必须来自该会话/明确选择的已保存资源，确认后保存副本并绑定精确版本，替换旧正式资源进归档；拒绝未确认、过期导图与并发变化。普通个性资源不被自动绑定。
- POST /api/course/resources {kbId,status:current|archive|trash|unlinked}；/resource {id,includeTrash?}：明确预览精确版本及稳定ID路径；/resource/action {id,action:archive|trash|restore|attach|purge,kbId?,nodeId?,expectedResourceId?,confirmed:true}：归档/回收站/恢复交换/关联/永久清除。删除资源不删除节点/导图/历史学习事件；非当前资源不出现在默认个性搜索和Agent总览。永久删除只清理本模块管理的副本/预览/索引，明确不等同清除原对话文字、用户原始资料或外部备份。
- POST /api/course/report {kbId,days?}：当前节点资源与手动完成/首次测验依据、历史时间线；归档不重复计分，资源份数/阅读量不换算掌握度。
- 删除KB：保存配置快照，当前图与节点资源转入可恢复状态；不删原始文件。/api/course/kb/restore {kbId,confirmed:true}恢复库与旧图，资源按可用位置明确恢复。会话删除不级联删已保存资源。
- 领域工具与接口同步：read_course_map、generate_course_map、publish_course_map、manage_course_node、list_course_resources、read_course_resource、manage_course_resource、get_course_progress、save_course_resource。工具依旧由Lumin按需选择，只有思维导图生成使用固定LLM流水线；写操作受用户明确意图和确认参数约束。
