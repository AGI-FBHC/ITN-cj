# 仓颉内核接口契约

外壳与内核之间的唯一通道。内核只监听 `127.0.0.1`，端口由系统分配，并把实际端口写入启动参数 `--port-file` 指定的文件。

## 启动参数

| 参数 | 说明 |
| --- | --- |
| `--data-dir <路径>` | 本地数据目录，默认 `%LOCALAPPDATA%\ITN-Desktop` |
| `--port-file <路径>` | 内核写入实际监听端口；外壳读取此文件完成握手 |

两种写法都支持：`--flag value` 与 `--flag=value`。

## 响应约定

成功：`{"code":0,"data":<内容>}`；失败：`{"code":1,"message":"<原因>"}`，并带对应 HTTP 状态码（400 参数问题、404 找不到、500 内部错误）。

## 接口一览

| 方法 | 路径 | 请求体 | 返回 |
| --- | --- | --- | --- |
| GET | `/health` | 无 | `{status, service, cangjie}` |
| GET | `/api/settings` | 无 | 见下方设置结构 |
| POST | `/api/models/save` | 模型配置 | 更新后的设置 |
| POST | `/api/models/delete` | `{id}` | 更新后的设置 |
| POST | `/api/models/roles` | `{chatModelId, embedModelId, chunkModelId}` | 更新后的设置 |
| POST | `/api/models/test` | `{id}` | `"连通"` |
| POST | `/api/chat` | `{modelId?, system?, user}` | `{reply, modelId}` |

## 设置结构

```json
{
  "models": [
    {
      "id": "openai",
      "name": "显示名称",
      "baseUrl": "https://api.example.com/v1",
      "apiKey": "",
      "hasApiKey": true,
      "model": "对话模型名",
      "visionModel": "多模态模型名",
      "embeddingModel": "向量模型名",
      "capabilities": ["text", "vision", "embedding"]
    }
  ],
  "chatModelId": "openai",
  "embedModelId": "openai",
  "chunkModelId": "openai"
}
```

三种用途分别绑定：`chatModelId` 对话与生成、`embedModelId` 向量化、`chunkModelId` 切片与图片描述（需支持多模态）。

## 安全与行为约定

- `apiKey` 永不回传，只回传 `hasApiKey` 布尔值。
- `save` 时若请求未带 `apiKey`（空字符串），保留原有密钥，避免外壳只改模型名时把密钥清空。
- `delete` 会同时清空引用该模型的三个用途绑定。
- 所有接口统一走 OpenAI 兼容格式：`POST {baseUrl}/chat/completions` 与 `POST {baseUrl}/embeddings`。

## 实现注意

默认的请求分发器按**精确路径**匹配，且不支持路径参数。因此所有路由都必须在 `core/src/api/api.cj` 的 `buildServer` 里显式注册；参数一律放在 JSON 请求体里，不用路径段和查询串。新增接口时记得同步那份路由列表。
