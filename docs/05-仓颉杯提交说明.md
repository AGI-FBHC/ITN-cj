# Lumin 系统说明

本说明面向2026仓颉杯创新原型赛道，说明桌面端的核心学习闭环、仓颉职责和复现方式。项目的完整说明还包括Web培训平台；两端分别部署和保存数据。

## 核心学习闭环

用户添加自己的教材或项目资料，建立知识库后检索原文并生成学习导图。Lumin 结合知识点范围与已保存的学习状态组织讲义、实操、测试或真实PPT课件。用户先预览，确认后收录学习资源，再通过随课对话、笔记、作答和复习继续学习。

桌面端提供独立会话和后台任务。一个会话执行任务时，可以切换或新建其他会话；任务中心展示状态。知识图谱生成显示进度和服务返回的token用量。学习状态区分本人阅读标记、自述目标偏好和真实作答记录，不因打开或完成阅读就认定已经掌握。

## 仓颉核心实现

- core/src/runtime：模型消息、事件、工具协议与Agent执行循环。
- core/src/runtime_host：学习工具接入、会话调度、任务状态、权限审批与上下文管理。
- core/src/model_provider：OpenAI兼容模型协议、流式输出与取消。
- core/src/workspace_tools：工作区文件工具、输出截断与草稿。
- core/src/kb、learning、course、study：资料索引、学习资源、知识结构、进度与复习记录。
- core/src/store、db、session：SQLite配置与学习数据、会话事件与恢复。
- core/src/api：本机HTTP接口与静态界面托管。

内核采用仓颉1.2.0，使用stdx.net.http、stdx.net.tls、stdx.encoding.json、std.fs与并发能力；数据库驱动使用仓颉实现。Electron负责窗口、系统文件选择和本地进程管理，前端使用JavaScript与CSS。

PPT制作由仓颉运行时调度固定流程，调用模型生成页面方案并输出真实可编辑的.pptx。文件生成与渲染按用途使用随包Python-pptx、Node/PptxGenJS及PDF.js等组件；其职责限于文档与课件处理。模型推理由用户配置的外部服务承担。

## 运行与复现

1. 解压按版本命名的Lumin压缩包，运行Lumin.exe。目标系统为Windows 10/11 x64，不要求安装仓颉SDK。
2. 在设置中填写模型地址、密钥和名称，并绑定对话模型；向量、图片理解和朗读模型按需要独立绑定。
3. 添加知识库。文件夹原地使用，单文件保存副本；选择“添加并索引”后，在知识库检索并核对原文。
4. 围绕一个知识点提出学习任务，查看工具过程和来源，预览资源，确认收录，再进行学习与练习。
5. 在学习记忆中检查目标、偏好和学习状态；开新会话继续提问，验证个性化上下文是否正确。

真实用户数据默认保存在%LOCALAPPDATA%\Lumin。更新前关闭旧版，备份数据库、资料目录和学习产物。

## 资料与文件边界

网页与仓库先进入本机暂存区，检查来源和内容后由用户确认并入知识库。并入与索引是两个阶段，索引失败可重建，不重复复制来源。GitHub来源固定完整commit。

普通会话按用户选择的权限审批访问。随课导学中的文件读写逐次由用户确认，附件和审批按会话隔离。调用外部模型时会发送问题、任务提示和所需资料片段；该功能需要相应服务的网络和账户权限。

## 验证证据

仓库tools目录包含可复现的检查脚本，TRACE.md记录每次范围、方法、失败样本与结果。2026年10月20日的验证包括176项核心测试、4次MiMo真实对话中的7项记忆检查、27项收集流程检查，以及桌宠边界、跨分页表格、配图和启动动画的真实浏览器检查。真实模型样例用于验证链路，不构成对学习成效的量化评估。

测试在临时数据目录运行，覆盖网页抓取、预览确认、索引失败重试、检索、重启恢复与跨会话遗忘等实际行为；临时夹具与真实模型调用在记录中分别说明。
