**桌面版当前状态**

## 二、目标形态

一个本地单机教培工作台：**一份 SQLite 数据库 + 一套本地 HTTP 接口 + 一个桌面窗口**。

- 数据全部落在本机一个 `.db` 文件里，可整体备份、可拷走。
- 除用户自己配置的模型服务外，不依赖任何外部服务。
- 界面覆盖网页版学习端的主要内容与交互，但只保留对单人本地使用有意义的部分。

## 三、为什么换成 SQLite

JSON 文件在数据量上来之后有三个硬伤：切片与向量要整份读进内存；统计类操作（正确率、完成度、按章节聚合）得自己遍历；增量修改要重写整个文件。SQLite 直接解决这三点，而且单文件、零服务、跨平台。

选型：`sqlite-driver`（<https://gitcode.com/zhangyin_gitcode/sqlite-driver>），**纯仓颉实现的 SQLite 驱动与嵌入引擎**，直接读写 SQLite 3 文件格式，不依赖本机 libsqlite3，实现标准库 `std.database.sql` 接口，Apache-2.0。

它的已知边界要一起认下来：不提供文件级 fsync，掉电持久化只能尽力；结果集在内存物化，不适合超大对象；只支持 UTF-8；不支持虚表、ATTACH、生成列、临时表、VACUUM INTO；递归 CTE 有行数上限；多进程写只在本驱动的进程间协调。这些对本产品都不构成阻碍。

## 六、风险与对策

| 风险 | 对策 |
| --- | --- |
| 驱动的目标平台名是 `x86_64-unknown-windows-gnu`，与我们的 `x86_64-w64-mingw32` 不一致 | 先做编译验证；必要时在依赖的 cjpm 配置里补我们的目标段 |
| 驱动按 `CANGJIE_STDX_PATH/windows_x86_64_llvm/dynamic/stdx` 组织，我们的 SDK 是 `windows_x86_64_cjnative` | 用路径依赖覆盖其 bin-dependencies，或改用我们已有的 stdx 路径 |
| 纯仓颉实现不保证掉电持久化 | 界面提供「导出/备份数据库」，关键操作后显式提交事务 |
| 结果集在内存物化 | 查询一律分页或加 LIMIT，不整表拉取向量 |

## 十三、第七轮：让"读不到我的资料"变成可见（2026-10-14）

真实用户的资料大量是 PDF/Word，而桌面版只能读纯文本类文件；此前遇到这种情况是**静默跳过**，
用户看到"没有找到文件"完全不知道问题在哪。本轮把这件事做成可见：

- 可读格式从 `.md/.txt` 扩到 `.md/.markdown/.txt/.text/.csv/.tsv/.log/.json/.html/.htm`；
  HTML 会先转文本（去 `script`/`style`，`h1`~`h6` → Markdown 标题，因此网页另存的资料照样按标题分章）。
- 新增扫描报告 `ScanReport`：按扩展名统计跳过的文件，随建索引结果回给界面（`skipped/skippedSummary/skippedTotal`），
  并写进 `meta`（`kb-skipped:<kbId>`），`/api/kb/stats` 可回传。
- 界面：建索引完成弹层用琥珀色提示「未纳入 N 个文件：pdf ×3、docx ×1」并说明原因与解决办法；

- 单文件 > 4 MB 跳过并计入「超过体积上限 ×N」；隐藏目录与 node_modules/target/dist 不扫描。
- 顺带加了工程保护：`scripts/package.ps1` 现在会**拒绝打包比源码旧的构建产物**——

## 十二、第六轮：可以随时停止生成（2026-10-14）

- 内核：新增取消登记表（`agent/cancel.cj`，`Mutex` 护住的 HashMap，用 sessionId 做键）与 `/api/agent/cancel`；
  流式回调里检查取消并抛 `CancelException`（继承 `LlmException`，这样 `postStream` 会原样重抛而不是包成网络错误）。

- 界面：对话输入框旁与生成进度卡上都出现「停止」；被取消的那一轮显示成灰色说明（不是红色报错），

- 实测（API 探针）：问答中途取消 502ms 返回 `cancelled:true`；讲义中途取消 1683ms、
  提示「已完成 1 小节」，产物数不变；取消后再发一轮正常（`clearCancel` 生效）。
- 两个必须记住的坑：
