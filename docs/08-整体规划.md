## 二、目标形态

一个本地单机教培工作台：**一份 SQLite 数据库 + 一套本地 HTTP 接口 + 一个桌面窗口**。

- 数据全部落在本机一个 `.db` 文件里，可整体备份、可拷走。
- 除用户自己配置的模型服务外，不依赖任何外部服务。
- 界面覆盖网页版学习端的主要内容与交互，但只保留对单人本地使用有意义的部分。

## 三、为什么换成 SQLite

JSON 文件在数据量上来之后有三个硬伤：切片与向量要整份读进内存；统计类操作（正确率、完成度、按章节聚合）得自己遍历；增量修改要重写整个文件。SQLite 直接解决这三点，而且单文件、零服务、跨平台。

选型：`sqlite-driver`（<https://gitcode.com/zhangyin_gitcode/sqlite-driver>），**纯仓颉实现的 SQLite 驱动与嵌入引擎**，直接读写 SQLite 3 文件格式，不依赖本机 libsqlite3，实现标准库 `std.database.sql` 接口，Apache-2.0。

它的已知边界要一起认下来：不提供文件级 fsync，掉电持久化只能尽力；结果集在内存物化，不适合超大对象；只支持 UTF-8；不支持虚表、ATTACH、生成列、临时表、VACUUM INTO；递归 CTE 有行数上限；多进程写只在本驱动的进程间协调。这些对本产品都不构成阻碍。

## 四、表结构

| 表 | 用途 | 关键字段 |
| --- | --- | --- |
| `settings` | 键值配置 | key, value |
| `models` | 模型接口 | id, name, base_url, api_key, model, vision_model, embedding_model |
| `roles` | 用途绑定 | role（chat/embed/chunk）, model_id |
| `knowledge_bases` | 知识库登记 | id, name, root_dir, doc_count, chunk_count, image_count, built_at |
| `chunks` | 切片 | id, kb_id, doc_path, doc_title, heading_path, ordinal, text, caption |
| `embeddings` | 向量 | chunk_id, kb_id, dim, vec（BLOB，Float64 数组） |
| `progress` | 阅读进度 | kb_id, chunk_id, read_at |
| `chapters_done` | 章节完成 | kb_id, chapter |
| `profile` | 学习者档案 | key, value |
| `notes` | 笔记 | id, kb_id, chapter, title, text, created_at, updated_at |
| `quiz_records` | 答题记录 | id, kb_id, chapter, question, my_answer, reference, correct, created_at |
| `sessions` | 会话 | id, title, created_at |
| `session_events` | 会话事件 | id, session_id, turn_id, kind, at, payload |
| `artifacts` | 产物 | id, name, path, size, created_at |

向量从 `vectors.txt` 文本改为 BLOB 列，读取不再需要解析几百万个浮点。

## 五、迁移顺序

1. **接入验证**：把驱动作为本地依赖接进 `core`，确认能在 Windows 上编译、建表、读写、事务。这一步不过，后面都免谈。
2. **存储层替换**：`store`、`kb`、`study`、`session`、产物登记逐个改为查库，接口签名不变，前端不受影响。
3. **数据迁移**：提供一次性的 JSON → SQLite 导入，保证已有配置与学习记录不丢。
4. **界面继续打磨**：补齐网页版里还没搬过来的部分（学习单元内的课件阅读、资源播放、画像与校准的更完整交互）。
5. **回归验证**：把现有验证脚本全部重跑，并补一套数据库相关的检查。

## 六、风险与对策

| 风险 | 对策 |
| --- | --- |
| 驱动的目标平台名是 `x86_64-unknown-windows-gnu`，与我们的 `x86_64-w64-mingw32` 不一致 | 先做编译验证；必要时在依赖的 cjpm 配置里补我们的目标段 |
| 驱动按 `CANGJIE_STDX_PATH/windows_x86_64_llvm/dynamic/stdx` 组织，我们的 SDK 是 `windows_x86_64_cjnative` | 用路径依赖覆盖其 bin-dependencies，或改用我们已有的 stdx 路径 |
| 纯仓颉实现不保证掉电持久化 | 界面提供「导出/备份数据库」，关键操作后显式提交事务 |
| 结果集在内存物化 | 查询一律分页或加 LIMIT，不整表拉取向量 |
