# 新前端接入方案｜半天首版

以当前28801页面为用户端基线，保留视觉、导航和学习流程，只做必要微调和功能补充。后端由你重写，采用仓颉1.1.3 + Spire；自建业务、Agent与任务服务均使用仓颉。优先快速部署、操作顺畅，不继承旧版复杂审批和反复审校。

## 1. 从旧系统带过来什么

| 用户看到的功能 | 迁移内容 | 处理方式 |
|---|---|---|
| 建档与个人档案 | 账号认证、画像、学习目标 | 保留现有问卷，保存到后端；补充轻量登录，不搬旧版建档页面 |
| 课程与学习计划 | 知识目录、已生成讲义、练习、测验 | 适配成当前课程卡片与课时；首版先打通一门内容完整的课程 |
| 阅读与PPT讲解 | 已有讲义、可用的结构化课件 | 沿用现有阅读器和PPT界面；不迁移旧播放器、不要求首版导出PPTX |
| 测验与学习进度 | 答题结果、掌握度、学习记录 | 后端判分并保存，刷新后仍能继续学习；进度页使用真实记录 |
| 书签与学习整理 | 课程收藏、片段书签；旧笔记、错题能力 | 先保存现有书签；笔记和错题后续加在学习页内，不增加复杂导航 |
| AI导师 | 课程上下文、引用、对话与记忆规则 | 后续用仓颉接模型；复用业务规则，不把现有Python转发链路带入 |
| 管理员端 | 课程/内容维护、资源直接发布、用户查看 | 另建同风格管理端；保存即可生效或一键发布，不设审批链；机构、邀请码、复杂报表暂缓 |

**不带入首版：**旧用户端整套界面、桌面壳、机构与部门流程、独立多智能体工作台、养成展示、复杂生成调度，以及多级审核、Agent互评、反复审校和置信度准入门槛。保留旧仓库作为参考，按功能抽取可复用仓颉代码。

## 2. 数据库怎么复用

| 用途 | 优先复用的表 |
|---|---|
| 账号与画像 | `users`、`user_profiles`、`learners`；会话表复用结构，旧登录会话不复制 |
| 知识与内容 | `knowledge_domain`、`knowledge_category`、`knowledge_category_prerequisite`、`generated_learning_resources` |
| 资料检索 | 按需复制 `knowledge_document`、`knowledge_chunk`、关联表及实际图片/文档文件 |
| 学习记录 | `quiz_results`、`knowledge_mastery`、`learning_events`、`study_sessions` |
| 后续功能 | `learning_notes`、`learning_wrong_answers`；对话、记忆与生成任务表到对应功能开发时再引入 |

- 只复制必要结构和筛选后的数据到隔离开发库，原`itn_cangjie_dev`保持不动；首版可从现有表中选择最小集合。
- 新增少量薄表：公共课程目录、课时与资源绑定、用户课时进度、书签。课程内容与个人学习状态分开，不把所有状态塞回JSON。
- 统一身份：账号与学习者显式绑定；旧库有多个学习者对应同一账号的情况，不能默认取第一条。
- **实际数据差异：**当前库97张表，145个知识目录节点全部属于Agent领域。前端有4门计算机基础课和1门Agent课；不能认为5门课的真实知识内容已经齐备。
- 库内545条生成资源按课程绑定后直接使用或由管理员一键发布，不搬旧审核状态机；8门生成课程属于个人数据，不能自动变成公共课程。首版选一门资料齐全的课程，其余保留课程入口并明确内容状态。

## 3. 半天交付范围

用户能完成：**建档 → 进入一门真实课程 → 阅读讲义/可用课件 → 测验 → 保存结果 → 刷新后继续学习**。

| 时间预算 | 工作 |
|---|---|
| 0—0.5小时 | 确认前端源码、选定课程和可用资源，固定最小接口与数据映射 |
| 0.5—2小时 | 抽取已有仓颉认证/数据读写，提供画像、课程、资源、答题和进度接口 |
| 2—3小时 | 当前页面接真实数据，保留布局；补充加载、空内容和失败重试状态 |
| 3—4小时 | 验证完整学习流程、刷新恢复、账号数据隔离，提交可回滚版本 |

这是目标预算，前提是源码与所需内容到位、已有仓颉模块可复用。**完整管理端、全部后端重写、实时AI生成及知识库导入不计入半天首版。**

## 4. 保证体验流畅

- 首页只加载摘要，课程和课时按需读取；不在进入页面时自动生成全课程内容。
- 优先展示已发布内容；后续生成放到后台，用户可继续浏览并查看任务状态。
- 后续AI功能先采用单次生成、基础格式校验与失败重试；不默认执行多轮审查、争论或额外模型评分。
- 问卷、收藏、进度及时保存；答案提交成功后更新学习状态，避免“看着完成、刷新丢失”。
- 新后端统一接口和响应格式，不保留旧系统多层转发与Python兜底；管理员直接维护内容，不让发布审批阻塞用户学习。

**启动条件：**当前本地只有线上打包产物，尚未拿到原始React源码。先找回源码；若需要等价重建前端，应单独估时，不能算入上述半天。Lumin/桌面代码需先适配并验证1.1.3，再计入可复用模块。

## 5. Lumin中值得抽取的能力

Lumin负责Agent运行时，学习生成等能力主要在Desktop宿主中。**抽取能力，不搬桌面工作台，也不先引入完整Agent工具循环。**

| 能力 | 接到新前端哪里 | 建议 |
|---|---|---|
| 模型调用、流式输出、停止与超时处理 | AI导师、讲义/PPT侧边问答 | 优先抽取，避免重写模型通信 |
| 讲义、实操、测验、幻灯片的结构化生成与渲染 | 现有阅读器、测验页、PPT页 | 复用数据格式与提示词，按用户需要只生成一种内容 |
| 文本切块、关键词/向量检索、引用编号 | 回答时引用课程资料 | 按需抽取；已有MySQL切片直接接入，存储层适配 |
| 答题、课时进度、同一材料继续修改 | 继续学习、错题解释、局部重讲 | 参考规则；数据读写优先用旧Web的1.1.3实现 |
| 目标偏好记忆、会话摘要、工具事件 | 后续个性化和生成状态 | 后置；先用现有问卷和课程上下文，不新增复杂面板 |

代码入口：模型通信在`apps/desktop/core/src/llm/`、`pi_provider/`；内容在`resource/`；检索在`kb/kb.cj`；学习状态在`learning/learning.cj`；运行时在`apps/desktop/lumin/src/pi/`。参考源码已检出到`D:\Downloads\ITN-cj-analysis-20261020`。

迁移时去掉自动返修轮次、字数/章节数硬门槛与桌面逐条审批；保留JSON可解析、题目答案有效、引用指向实际资料等基础检查。CLI任意文件/命令工具不接入网页端。PPTX导出依赖Python/桌面制作链，不迁移，沿用当前网页幻灯片。
