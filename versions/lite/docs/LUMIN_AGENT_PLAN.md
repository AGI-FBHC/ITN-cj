# Lumin Agent 工作区方案（已记录，尚未实现）

## 目标

把当前的 Lumin 对话升级为真正的个人学习 Agent。每个用户在数据库中有一份长期学习
记忆，并在服务器上有一个隔离工作区，用于存放由 Lumin 生成的临时笔记、练习草稿、
检索缓存和任务附件。用户只能通过 Lumin 服务读写自己的工作区。

## 与当前版本的关系

当前版本已经实现或正在实现：

- AI 导师产品名统一为“Lumin”，系统提示词使用“用户的个人学习助手——Lumin老师”。
- `user_learning_memory` 保存用户专属学习画像和长期记忆，Lumin 每次回答前读取。
- `GET /api/learner/memory` 供“我的画像”页面读取当前用户记忆。

本文件描述的 Agent 工作区与文件工具不在当前交付范围内，后续单独设计和验收。

## 已记录的产品约束

1. 每个用户单独一个目录，目录名使用不可反推个人信息的 UUID。
2. 目录根由服务端配置，默认建议 `data/lumin/workspaces/{userId}/`，不得接受客户端传入绝对路径。
3. 用户只能读写自己的目录；管理员排障也必须经过审计授权，不能静默越过。
4. Lumin 工具只提供目录内相对路径，拒绝 `..`、符号链接逃逸、盘符切换和保留设备名。
5. 写入限制文件类型、单文件大小、目录总配额和并发数；禁止执行上传文件中的脚本。
6. 临时文件有 TTL，后台按最后访问时间定时清理；长期记忆在数据库，不依赖目录永久存在。
7. 重要内容需要提升为数据库记忆或用户可见资源，避免清理后丢失。
8. 删除、批量移动、导出等动作必须可审计；密钥、Cookie、真实用户隐私不写入目录日志。

## 建议目录结构

```text
data/lumin/workspaces/{userId}/
  scratch/        # 临时草稿，默认 7 天 TTL
  notes/          # 可提升为长期记忆的学习笔记，默认 30 天 TTL
  attachments/    # 本轮任务附件，默认 1 天 TTL
  cache/          # 检索或生成缓存，可直接重建
  manifest.json   # 配额、最后访问时间、清理策略和文件索引
```

## 建议接口边界

- `GET /api/lumin/memory`：读取当前用户长期记忆。
- `PUT /api/lumin/memory`：仅由受控 Agent 流程更新，记录版本和来源。
- `POST /api/lumin/workspace/session`：为一次 Agent 任务创建或复用隔离会话目录。
- `POST /api/lumin/workspace/cleanup`：管理员按策略触发；默认由后台定时任务执行。

## 验收条件（后续实现时）

- 两个用户互相构造路径时无法读取对方文件。
- `..`、符号链接、绝对路径和超大文件均被拒绝。
- 服务重启后记忆仍可从数据库恢复，临时目录可按 TTL 清理。
- 清理不会删除数据库长期记忆或已发布学习资源。
- 真实 Agent 回答可以引用当前用户记忆，且不会把其他用户记忆带入上下文。
