# 前端接口对接与变更记录

> 仓库 `ITN-cj` 的 **`front`** 分支 = 网页版前端（React 19 + Vite + TypeScript + Tailwind）。
> 内容就是主仓库 `src/front` 的前端代码，**保留了完整提交历史（942 条）**（从主仓库用 `git subtree split` 拆出，路径已重写为仓库根）；后端 Spring Boot、Agents FastAPI 不在本分支。
> 最近提交的快速索引见 `DEVELOPMENT-HISTORY.md`；更细的逐条记录在主仓库 `docs/change-trace.md` 与 `docs/frontend/*.md`。

## 一、连接与约定（改接口前先看这段）

| 项 | 约定 |
| --- | --- |
| 开发代理 | `/api` → `http://localhost:8080`（后端）、`/v1` → `http://localhost:8100`（Agents）；用 `VITE_API_PROXY_TARGET` / `VITE_AGENT_BASE` 覆盖 |
| 生产地址 | `VITE_API_BASE`（默认空 = 同源）；见 `vite.config.ts` 的 `server.proxy` |
| 鉴权 | `Authorization: Bearer <JWT>`，token 存在 localStorage |
| 响应外壳 | `{ code, message, data, timestamp }`，`code === 0` 表示成功 |
| 单一真源 | **`src/lib/api.ts`** —— 所有接口函数与 TS 类型都在这里；改接口先改它 |
| 请求助手 | `request`（解开外壳）/ `requestDirect` / `requestAgent` / `requestAgentEtag` |
| 开发服务注意 | dev server 必须双栈监听（`vite.config.ts` 里 `server.host: '::'`）。只监听 IPv4 时，本机 `localhost` 会先解析到 `::1`，每个请求白等约 2 秒，首屏会表现成"一直在加载、刷新又好了" |

## 二、接口变更记录（新的写在最上面）

### 2026-10-15 新增「学习目标」learning-goals（在飞，前后端都要看）

| 方法 | 路径 | 请求体 | 响应 |
| --- | --- | --- | --- |
| GET | `/api/v1/learning-goals` | — | `LearningGoal[]` |
| POST | `/api/v1/learning-goals` | `LearningGoalInput` | `LearningGoal` |
| PUT | `/api/v1/learning-goals/{goalId}/current` | — | `LearningGoal` |

字段（定义在 `src/lib/api.ts`）：

- `LearningGoal`：`id, knowledgeDomainId, knowledgeDomainCode, knowledgeDomainName, goalType, title, description|null, expectedLevel, initialLevel|null, assessmentMethod|null, status, targetDate|null, current(bool), createdAt, updatedAt`
- `LearningGoalInput`：`knowledgeDomainId, goalType, title, description?, expectedLevel, status, targetDate?`

**后端配套改动（需后端同学同步）**：`LearningGoalResponse` 里 `title` 原本写成
`domain == null ? goal.getTitle() : domain.getName()`，导致列表里显示的是领域名（例如全是「智能体」）而不是目标标题；
已改为直接用 `goal.getTitle()`。这条改动目前**还在主仓库工作区、尚未提交**。

**状态**：这三个接口的前端调用（`src/lib/api.ts`）与报告页 UI（`src/pages/Report.tsx`）也处于未提交状态，
本分支已把这两个文件一并带上，便于对接。`tsc` 通过（基线 18 个历史报错，本次新增 0）。

### 2026-10-14 掌握度回写 `/api/v1/learner-profile/quiz`（前端补齐调用）

- 接口早已存在，但前端此前从未调用 → 学员画像的掌握度一直是空的。
  现在三个作答入口（课件播放页、伴学浮窗练习卡、完整阅读页）都会上报。
- 无破坏性变更，只是补齐调用；字段以 `src/lib/api.ts` 中对应函数为准。

### 2026-10-14 待后端决定的接口问题（不是前端 bug）

1. `GET /api/v1/admin/predeal/health` 返回 **403 `该内部服务路径未在平台白名单中开放`**，
   管理端健康矩阵该行永远不可能显示为正常。需要二选一：把该路径加入白名单，或从管理端移除此行。
2. `/api/v1/learning-path`、`/api/v1/review-states`、`/api/v1/knowledge-points` 仍返回旧赛题知识点
   （`kp-ds 数据结构与算法`、`kp-co 计算机组成原理` 等），而前端已切到 21 章「智能体」体系。
   前端除报告页锚点外**没有调用**这几个接口，建议后端确认是否下线或迁移。

### 2026-10-13~14 数据口径说明（避免对不上数）

领域知识库页显示的 **119 知识节点 / 28 来源文档 / 1,472 知识切片 / 207 知识配图** 来自
`/api/v1/rag/domains`（RAGFlow 索引）；平台库侧是 1755 切片 / 537 资源；KnowledgeCore 是 145。
三套口径互不可比，界面上已写明这一点。

### 2026-10-14 环境问题（已修复，记录备查）

`/api/v1/rag/*` 曾整片 30 秒超时后 500：云端开发库账号 `itn_cj_dev` 是按**来源 IP** 授权的，
本机公网出口变化后不在授权列表里，MySQL 一律返回 1045 且不校验口令（所以换密码无效）。
已在库上补授权后恢复（`/api/v1/rag/domains` 1.6s/200）。**换网络后可能复发**：
先比对"当前出口 IP"与 `mysql.user` 里的来源列表。

## 三、怎么维护这份记录
